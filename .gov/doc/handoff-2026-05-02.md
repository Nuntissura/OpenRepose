## The six rules. Read them. They are non-negotiable.

Full bodies in `.gov/AGENTS.md`. Compact list in `.gov/CODEX.md`. Machine-readable in `.gov/topology.yaml` `repo_rules:`. Audit-enforced quarterly via `scripts/audit-repo.ps1`.

1. **Work-Start Protocol** — you do not edit `.product/` until a WP at READY/IN-PROGRESS exists, has a taskboard row, and has been committed and pushed.
2. **Pre-Work Commit Rule** — `git add -A && git commit && git push` succeeds with the WP file before you open any product file in your editor. The reason is the survival rule below.
3. **Naming Convention** — no blank-space characters in any committed path inside the repo. kebab-case for docs and WPs, snake_case for Python.
4. **Disk-Agnostic** — no hardcoded absolute paths in any committed file. The repo runs on any drive, any machine.
5. **Research-First** — before non-trivial implementation, research GitHub, Hugging Face, Civit AI, vendor docs, arXiv, forums. Record findings in the WP's `## Research Notes` table with date + source URL + verdict.
6. **Deletion Protocol** — never run manual `rm` / `Remove-Item` / `del` on tracked files or repo folders. Use `/safe-delete` (`.claude/commands/safe-delete.md`) or `scripts/safe-delete.ps1`.

The reason the rules exist: prior projects lost product code to wrong-tool / wrong-cwd accidents — wrong git tooling, accidental directory climbing, scripts that deleted parents of parents. One incident took an entire disk. The rules make that class of error structurally impossible.

## Two I0 pitfalls that already cost real time

Already fixed in code. Worth knowing because they are subtle and will be tempting to "fix again" if you misread the symptoms.

- **head_anchor in `rig.py`**. Originally set to `body_kps[1]` (MediaPipe `left_eye_inner`), which made shoulders fly off-canvas at non-zero yaw. The fix is to synthesize the head anchor as the mean of MediaPipe shoulder indices 11 + 12 (a real neck-bottom estimate). Do not change this back without understanding why.
- **z-scale mismatch between FaceMesh and Pose**. MediaPipe Pose returns z-values roughly 10× larger than FaceMesh z-values. Calibrate per-portrait via the nose-tip ratio: `body_kps[:, 2] *= fm_nose_z / pose_nose_z`. See `Rig.from_portrait()`. If shoulders look "deeper than the face" at non-zero yaw, this is what to check first.
