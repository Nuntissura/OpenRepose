## How to start a WP — the proven sequence

Demonstrated end-to-end in commits `8e1c00a` (kickoff) → `e154bb6` (implementation) for WP-I1-025. Mirror it:

1. Read the WP file, the spec sections it cites, and any predecessor WPs.
2. Do the **Research-First** pass. Update the WP's `## Research Notes` table with sources + dates + verdicts. If research changes the Reality Boundary or Definition of Done, edit those sections.
3. Move WP status from `DRAFT` to `READY` in the WP file. Add a row to `TASKBOARD.md` under "Active". If the WP is already at `READY` (rare), skip.
4. **Commit + push the WP file + taskboard row only.** Commit message: `WP-IX-NNN: kickoff — <one-line>`. Push must succeed before step 5.
5. Move to `IN-PROGRESS`. Implement in `.product/` (and `scripts/` / `.github/` if needed; the latter two are exempt from rule 1 only when their change is governance-flavored — touching `scripts/safe-delete.ps1` is product work).
6. Run `pytest`. Save junit XML to `target/test-artifacts/WP-IX-NNN/`. Run `pwsh scripts/audit-repo.ps1` to confirm no rule drift introduced.
7. Move to `REVIEW`. Update Change Ledger and Evidence sections truthfully. Move the taskboard row from "Active" to "Pending Review".
8. Commit + push the implementation. Wait for operator sign-off before moving to `DONE` and archiving.

## Two pitfalls already burned in I0

These are documented in commit messages and WP archives but worth flagging.

- **head_anchor**: Initially set to `body_kps[1]` (MP `left_eye_inner`) which caused shoulders to fly off-canvas at non-zero yaw. Fix: synthesize as the mean of MP shoulder indices 11 + 12. See `.product/src/openrepose/rig.py`.
- **z-scale mismatch between FaceMesh and Pose**: MediaPipe Pose z-values are roughly 10× larger than FaceMesh z-values. Calibrate via the nose-tip ratio: `body_kps[:, 2] *= fm_nose_z / pose_nose_z`. See `Rig.from_portrait()`.
